# Architecture

A map of the codebase for reviewers. For the protocol (how encrypted DNA,
peek/open/reveal, the Blind Arena and the launchpad work), see the
[README](../README.md); this document is about how the four packages fit
together and how code and data flow between them.

## Packages

```
art/         TypeScript renderer and trait tables — the single source of truth for the art
contracts/   Hardhat project: the Solidity contracts, generated on-chain art, tests, deploy and admin tasks
web/         Mint site (Vite + React 19 + wagmi + @cofhe/sdk) and its Playwright end-to-end tests
landing/     fhecat.com: static site plus the Vercel serverless functions (waitlist, collab, admin)
tools/       Pixel-font generator for the landing page
```

### `art/` — the art, once

`art/src` holds the sprites (`sprites/`), the trait tables and rarity weights
(`traits.ts`), the pixel renderer (`render.ts`, `art.ts`), the arena fighters
(`fighter.ts`, `fighterPoses.ts`, `arena.ts`) and a compiler (`compile.ts`).
This TypeScript renderer is the source of truth for every FheCat image. It is
used in two places that must agree exactly:

- **On-chain:** `compile.ts` packs the sprite data into a Solidity library,
  generated into `contracts/contracts/art/FheCatArt.sol` by
  `npm run art:sol`. `FheCatRenderer.sol` draws from it.
- **In the browser:** `web/` imports the same TypeScript renderer so a private
  peek can draw the cat locally, without the plaintext DNA ever leaving the
  device.

Contract tests enforce byte-for-byte parity between the two, so the two
renderers can never drift.

### `contracts/` — Hardhat

```
contracts/contracts/
  FheCat.sol          ERC-721: encrypted DNA at mint, peek / open / reveal, ACL management
  FheCatArena.sol     Blind Arena: encrypted tactics, scoring under FHE, tiers, weekly table
  FheCatRenderer.sol  On-chain SVG renderer (no FHE calls)
  art/FheCatArt.sol   Generated sprite library (regenerated by `npm run art:sol`)
  interfaces/         Shared interfaces
  launchpad/          FheLaunchpad, FheLaunchToken, FheCatRewards (dual-mode ERC-20 + fee share)
  mocks/              FheCatLocal, FheCatArenaLocal — local-only subclasses that stub the random draw
scripts/              deploy.ts, deploy-launchpad.ts, gen-art-sol.ts, preview-art.ts, export-abi.ts
tasks/                Hardhat tasks: fhecat.ts (collection), arena.ts (duels), lib.ts (shared helpers)
test/                 Contract tests against the CoFHE mocks
test/fork/            Fork tests against a live CoFHE TaskManager
```

The CoFHE mocks cannot produce encrypted randomness, so the local chain
deploys the `*Local` subclasses, which replace only `FHE.randomEuint64()` and
refuse to deploy to any chain other than 31337. The real randomness path is
covered by the fork tests and the live testnet.

### `web/` — mint site

Vite + React 19 + wagmi + `@cofhe/sdk`. `src/App.tsx` is the mint and cat
viewer, `src/LaunchpadApp.tsx` the launchpad, with `arena/` (the live fight and
replays), `components/`, `lib/` (chain and CoFHE helpers), `pixel/` (the shared
renderer glue) and `config/` (`deployments.json`, written by the deploy
script). `e2e/` holds the Playwright suite; `e2e/stack.sh` brings up a local
chain, the CoFHE mocks, a deploy and the site for a full end-to-end run.

The build also produces the two copies served by the landing site:
`build:testnet-copy` writes the public copy at `fhecat.com/testnet/`, and
`build:admin-copy` writes the admin copy. `build:admin-game` writes the arena
game bundle used by the admin panel.

### `landing/` — fhecat.com

Plain HTML/CSS/JS on Vercel with serverless functions and a Neon Postgres
database. See [`landing/README.md`](../landing/README.md) for the pages, the
API endpoints and the environment variables.

## Data and build flow

```
art/src  ──(npm run art:sol)──▶  contracts/art/FheCatArt.sol  ──▶  FheCatRenderer.sol  (on-chain art)
   │
   └──(import)──▶  web/ renderer  ──▶  private peeks and the arena fight  (same image, in the browser)

contracts deploy  ──▶  contracts/deployments/<network>.json
                  └──▶  web/src/config/deployments.json       (addresses the site reads)

web build:testnet-copy / build:admin-copy  ──▶  landing/testnet/ and landing/admin/mint/
web build:admin-game                        ──▶  landing/admin/mint/arena-game.js
```

Two generated artifacts are committed and checked in CI so they can never fall
behind the source: `contracts/art/FheCatArt.sol` (from `art/src`) and
`landing/admin/mint/arena-game.js` (from `web/`).

## Continuous integration

`.github/workflows/ci.yml` runs three jobs on Node 22:

- **contracts** — `npm ci`, `hardhat compile`, a check that the generated art
  library is up to date (`npm run art:sol` leaves no diff), then `npm test`.
- **web** — builds the contracts and the site, checks the admin arena game is
  built from the current code (no diff), installs Chromium and runs the
  Playwright end-to-end suite against a local chain and the CoFHE mocks.
- **landing** — syntax-checks the site scripts, `middleware.js` and the Vercel
  functions in `api/` with `node --check`.

Dependabot (`.github/dependabot.yml`) proposes weekly updates for the three npm
lockfiles and for the SHA-pinned workflow actions.

## Chains

FheCat contracts run on Ethereum and other EVM chains; Fhenix CoFHE is an
off-chain FHE coprocessor reached through the `TaskManager` contract, found via
the `CoFHEAddressBook` at the same address on every chain. See the README's
"Networks" and "Fhenix is a coprocessor, not a chain" sections for the full
picture.
